# virtualUSB error map

Match the client's output (stdout and stderr together) against the **Symptom** column, then report `<Meaning> → <Next step>` in plain language. Never retry the same command in a loop; each row says whether one retry is allowed. `vusb` exit codes are not a reliable signal — parse the text.

| Symptom (exact / regex) | Meaning | Next step |
|---|---|---|
| `Authorization info not found. Please login to your Kobiton's account first!` (printed by `connect`, `disconnect`, `status`) | The client has no saved sign-in on this machine | Run `~/.kobiton/bin/vusb login` (the wrapper injects `--apibaseurl`, `--username`, `--apikey` from `~/.kobiton/.credentials`), then retry the failed command once. If `login` itself fails with `Missing KOBITON_…`, run `/automate:doctor`, then `/automate:setup`. |
| `Authentication error:` with anything other than the row above (invalid key, 401, 403) | The saved API key was rejected | Run `/automate:setup` to refresh `~/.kobiton/.credentials`, then `~/.kobiton/bin/vusb login` again. Stop if it fails a second time. |
| `virtualUSB is not included in your current subscription` | The organization's plan has no virtualUSB add-on | Stop. Tell the user their Kobiton organization admin must enable virtualUSB on the subscription; nothing on this machine fixes it. |
| `Failed to connect to dcb app server: Connection refused` (inside `Failed to get status: DcbStatusError { … }`) | The client's background daemon is not installed or not running yet | On macOS the first `vusb connect` (and every version bump) installs the daemon through an administrator dialog in the GUI session — run `connect`, tell the user to approve the dialog, do not retry `status` in a loop. Over SSH / without a GUI session the daemon cannot be installed: stop and hand off. On Windows, run `vusb setup-adb` in an administrator terminal (see the preflight hand-off steps). |
| `Connect failed:` + `timed out`, `unreachable`, `connection reset`, `no route to host`, `dns`, `TLS` | The device's host machine cannot be reached from this network | Check VPN / proxy on this machine, then confirm the host machine's virtualUSB routing in Portal → Device Management (the machine that hosts the device). Retry `connect` once after the network changes; otherwise stop. |
| `already retained`, `already connected`, `in use`, `booked`, `is being used by` | Another session or user holds the device (manual, automation, or another virtualUSB client) | Do not wait on it. Offer `listDevices({virtualUsb: true})` to pick another ready device, or tell the user to ask the holder (or a Portal admin) to release it. |
| `vusb --version` token ≠ the pin in `VUSB_VERSION`, or the wrapper prints `Warning: pinned virtualUSB version … is not cached` | The client in use is not the build this plugin release was validated against | Re-run the preflight: `bash <plugin-root>/skills/debug-device-over-vusb/scripts/vusb-preflight.sh`. If it reports `handed off to human`, relay its stderr (system install at another version, or the pin is no longer published — update the automate plugin). |
| Picked device `platform_name: "iOS"` while `uname -s` is `MINGW*`/`MSYS*`/`CYGWIN*` | iOS devices are list-only on a Windows host | Stop before `connect` unless the user only wants the device listed; direct them to a macOS host for Xcode-based debugging. |
| `vusb status` shows the device connected, but `adb devices -l` does not list it | The local adb server started before the virtual device appeared | Run `adb kill-server`, `sleep 3`, `adb devices -l` once. Still empty → `~/.kobiton/bin/vusb disconnect --udid <udid>` then `connect` once more. Still empty → stop and report; leave the device disconnected (Step 9). |
| `adb: device unauthorized` / `unauthorized` in `adb devices -l` | The device has not trusted this computer's adb key | Tell the user to accept the "Allow USB debugging" prompt on the device's screen (via the Portal live view if needed), then re-check `adb devices -l` once. |
| `error: The following required arguments were not provided: --udid <udid>` | `connect` / `disconnect` was called without the UDID | Re-issue the command with `--udid <udid>` from the picked device. |
| Preflight exit 1 with `checksum mismatch for macos.pkg (<version>) - download discarded, existing cache untouched.` | The downloaded package did not match its published sha256 (corrupted or tampered) | Retry the preflight once; if it repeats, stop and report it on the plugin repository. Any existing cache is intact. |
| Preflight exit 1 with `could not fetch checksum for <version> (HTTP <code>) - refusing unverified install.` | The `.sha256` sibling could not be fetched, so the download cannot be verified | Retry once when the network is stable; otherwise stop. Nothing unverified is ever installed. |
| Preflight `outcome=redirected (limitation)` | This host OS is not supported by the skill | Stop; see `references/limitations.md` (Linux host). |
